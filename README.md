# 留學生活儀表板

個人留學生活的六向度儀表板：把「學習、社交、能量、經濟、探索、反思」六個面向的投入記錄下來，用六角形快照看每一期(週/月)的平衡狀態，用格拉斯哥地圖上的城市視覺化看長期累積的成長。這是整個專案的 v3 版，概念上跟先前的「餘裕管理」版本完全不同，資料庫也是全新設計，不相容舊版資料。

## 核心概念

- **一張表打天下**：所有紀錄(日期、向度、描述、投入程度 1-5)存在同一張 `entries` 表。要嘛是「事前已知的計畫」(藍)，要嘛是「行程外的行動」(橘)——不用另外選，系統自動比對「輸入當下的日期」跟「事件日期」：提前輸入 = 計畫；當天輸入 = 行程外。
- **六角形快照**(儀表板)：可切換週/月，可翻上一期/下一期。橘色面積是這一期的總投入，藍色疊在上面是其中「事前排定」的部分，露出來的橘色邊緣就是臨時決定的行動。某個向度佔比過高、另一個幾乎掛零時，會跳出溫和的失衡提醒。
- **城市視覺化**：六個向度各自釘在格拉斯哥地圖上一個你自己選的真實地點，建築物依累積投入分 12 級(1 樓平房到 12 樓大樓)，六種向度各有固定的造型(學習=平頂塔、社交=尖頂塔、能量=圓頂塔、經濟=階梯塔、探索=斜頂塔、反思=簡約矮塔)跟顏色，長期累積、不會歸零。點建築可以看該向度所有紀錄的清單。
- **隨手記**：未開始的想法先寫下來，之後一鍵「轉為紀錄」，選向度、日期、強度後就會變成正式的一筆。

### v3.1 調整

- 手動輸入(含未來行程、隨手記轉紀錄)的向度選擇改用英文標籤
- 城市頁拿掉 Leaflet + OpenStreetMap，改成純靜態的 2.5D 插畫(跟六角形一樣不需要任何外部地圖服務)，不能點擊、不用設定地點，單純呈現六座建築沿克萊德河分布的樣子
- 新增「未來行程」頁，可以一次登記多筆已知的未來計畫，下方會列出所有還沒到的計畫

### v3.2 調整（部署前的快速調整）

- 「Social」向度改名為「Relationship」（中文標籤也一併從「社交」改成「關係」，如果你只想改英文、中文要留著「社交」，跟我說一聲就改回來）
- 「手動輸入」跟「未來行程」合併成一個「輸入」頁，上方用切換鈕選「今日行動」或「計畫/行程」
- 「計畫/行程」跟「今日行動」的藍橘分類，從原本自動比對日期，改成**輸入當下由你明確選擇**——資料庫新增了 `kind` 欄位（'plan' 或 'action'），不再用「輸入時間點 vs 事件日期」反推
- 「今日行動」模式不顯示日期欄位（固定當天）；「計畫/行程」模式才會出現日期欄位，預設是明天
- 隨手記的「轉為紀錄」彈窗也加了同樣的切換鈕

### v3.3 調整：滿意度

- 每筆紀錄新增「滿意度」評分(5 點量表，跟投入程度分開評，必填)
- 新增第二種提醒：這期投入最多的向度，如果平均滿意度偏低，會跳出「要不要想想是不是方法需要調整」的提醒(跟失衡提醒是分開的兩張卡片)
- 城市建築的顏色飽和度現在會反映該向度的全時間平均滿意度：滿意度低 → 顏色偏灰；滿意度高 → 顏色飽和。樓層高度依然只代表投入量，兩者是分開的兩個訊號
- 想調整判斷門檻：`lib/calc.js` 的 `SATISFACTION_LOW_THRESHOLD`(多低算偏低)、`MIN_ENTRIES_FOR_SATISFACTION_ALERT`(至少幾筆資料才提醒)

### v3.4 調整

- 城市頁新增互動：點建築可以看到該向度的行動清單(名稱、日期、投入、滿意度、計畫或行動)
- 輸入頁的日期欄位永遠顯示，兩個類別(今日行動／計畫行程)預設都是今天，可以自由改成任何日期——分類(藍/橘)只看你選的類別，不會因為日期而改變，這點上一版邏輯其實已經是這樣，這次只是把介面也改得更直覺一致

### v3.6 調整：投入與滿意度徹底分開評分

- 拿掉「今日行動/計畫行程」的類別(kind)整個概念——這個設計有個邏輯漏洞：計畫的當下根本不會知道滿不滿意
- 輸入頁只剩：日期、向度、描述、投入程度。滿意度不再是輸入當下的欄位
- 新增「滿意度」頁：以日期分組列出過去到今天的紀錄，每筆可以事後用 5 點量表評分，評了會即時反映到儀表板
- 六角形不再是「藍色疊在橘色上」的堆疊關係，改成**兩個各自獨立、疊在一起的形狀**：藍色(投入量，不透明)、橘色(已評分的滿意度加總，30% 透明)——兩者是不同的事，不再有誰包住誰
- 資料庫：`entries.satisfaction` 改成可以是 NULL(代表還沒評)，拿掉 `kind` 欄位

### v3.7 調整

1. 雷達圖的畫法順序改成明確指定：投入(藍)當底層先畫，滿意度(橘)後畫疊在最上層
2. 「輸入」頁的最近紀錄新增「編輯」按鈕，可以改向度、日期、描述、投入程度
3. 最近的紀錄改成用週分頁瀏覽(上一週/本週/下一週)，不會因為紀錄越存越多而一直往下長
4. 滿意度的呈現邏輯改成「比例」：投入 1、滿意度 1 = 比例 1(=100%，剛好符合預期)；投入 5、滿意度 1 = 比例 0.2(投入很多回報很少)。雷達圖橘色 = 比例 × 投入量，不再是滿意度分數直接加總。城市建築的色澤也改用這個比例(1=飽和原色，趨近 0 則偏灰)
5. 輸入邏輯改成「以事情為主」：向度改成可複選(例如「跟朋友去 IKEA」可以同時勾「Relationship」跟「Exploration」)，一筆紀錄會用全額投入量分別算進每個勾選的向度。資料庫的 `dimension` 欄位改成 `dimensions` 陣列

### v3.8 調整

1. 滿意度計算改回原始數值加總，拿掉上一版「比例(滿意度/投入)」的加權邏輯——雷達圖橘色現在就是已評分項目的滿意度分數直接加總，城市建築色澤也改回用平均分數(1-5)判斷，不是比例
2. 雷達圖藍色(投入量)改成完全不透明的實色，只有橘色(滿意度)維持 30% 透明，兩色的視覺對比更清楚
3. 城市頁點建築看到的紀錄清單，改成用月份分頁(上一月/本月/下一月)

### v3.9 調整

## 部署到 Render

跟先前版本相同：

1. 把這個資料夾推到你的 GitHub repo(`git add . && git commit -m "v3 study abroad dashboard" && git push`)
2. Render Dashboard → 你原本的 `margin-app` Web Service，因為連的是同一個 repo，push 上去後 Render 會自動重新部署
3. **注意：這次資料庫結構整個換了**(舊的 `events`、`growth_stats`、`weekly_plans` 等表都不再使用，換成 `entries`、`quick_notes`、`building_locations`)。`db/schema.sql` 用的是 `CREATE TABLE IF NOT EXISTS`，不會主動刪掉舊表，但舊表的資料也不會再被讀取——如果想徹底乾淨，可以到 Render 的資料庫 Shell 手動 `DROP TABLE` 掉舊表，非必要，但比較整潔

## 地圖說明

城市頁是**純靜態的 2.5D 插畫**（跟儀表板的六角形一樣是純前端畫的 SVG），不會連任何外部地圖服務，也不需要設定真實地點——六座建築的版面位置是固定的，只有樓層高度會依累積投入即時變化。

## 想調整數值時去哪裡改

- **升級門檻(幾分升到第幾樓)**：`lib/calc.js` 最上面的 `LEVEL_THRESHOLDS` 陣列，12 個數字對應 12 個等級
- **失衡提醒的判斷標準**：`lib/calc.js` 的 `computeImbalance()`，裡面的 `HIGH_THRESHOLD` / `LOW_THRESHOLD`
- **建築造型/顏色**：`public/buildings.js` 的 `DIM_CONFIG`
- **地圖預設中心點**：~~`public/app.js` 最上面的 `GLASGOW` 座標~~（v3.1 起城市頁改成靜態插畫，不再需要這個設定）；建築版面位置在 `public/buildings.js` 的 `CITY_LAYOUT`
